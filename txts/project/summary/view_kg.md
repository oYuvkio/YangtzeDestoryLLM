# 基于大语言模型的长江流域水旱灾害知识图谱构建

> 本章介绍基于大语言模型实现长江流域水旱灾害知识图谱的构建过程。在模式层中，采用**专家骨架引导 + 语料聚类**的混合本体构建方法；在数据层中，提出**图结构嵌入 Prompt + 链式思维（CoT）**的信息抽取方法，并结合**原文回溯校验**机制过滤幻觉。

---

## 1 问题描述

长江流域水旱灾害知识图谱可以将灾害事件、致灾因子、影响区域、应急响应等关键要素及其之间的关系以三元组的形式结构化存储，支撑灾害风险识别、事件溯因分析、应急决策支持等智能化应用场景。然而，现有知识图谱构建方法面临以下挑战：

1. **本体构建困难**：水旱灾害领域概念繁杂，纯专家定义难以覆盖语料中的长尾概念，而纯数据驱动方法又容易引入噪声。

2. **信息抽取不稳定**：灾害文本结构复杂，包含事件描述、统计数据、调度规则等多种类型，传统 Prompt 难以系统性地指导 LLM 进行关系连接。

3. **幻觉问题严重**：LLM 容易生成原文中不存在的实体或关系，降低知识图谱的可信度。

为解决上述问题，本章做出以下研究工作：

（1）**构建了混合本体（Hybrid TBox）**。结合领域专家预定义的骨架本体与语料驱动的聚类发现，通过 K-means 聚类、Dice 系数相似性度量和支持度/置信度筛选，完成水旱灾害领域本体的自动化构建与质量控制。

（2）**提出了图结构嵌入 Prompt + 增强 CoT 的抽取方法**。根据文本类型自动检测并选择对应的图结构模板，将实体角色（起始/中间/终止节点）和关系路径嵌入 Prompt，引导 LLM 按链式步骤进行实体识别、关系连接和证据回溯。

（3）**设计了原文回溯校验机制**。通过精确匹配和模糊匹配相结合的方式，验证抽取结果是否在原文中有明确的文本证据，有效过滤幻觉三元组。

### 2.1 模式层构建：专家引导 + 语料聚类的混合本体

模式层是知识图谱的概念模型和逻辑基础，定义了实体类型（classes）、关系类型（relations）和属性（attributes）。本文提出专家骨架引导与语料聚类相结合的混合本体构建方法，兼顾领域知识的准确性和语料覆盖的完整性。

#### 2.1.1 专家骨架定义

根据《长江流域防汛抗旱应急预案》《水旱灾害防御应急响应工作规程》等规范性文件，预定义水旱灾害领域的核心概念作为锚点（Anchor），包括：

**实体类型**（14 类）：
- 灾害事件类：DisasterEvent（灾害事件）、FloodEvent（洪水事件）、DroughtEvent（干旱事件）
- 致灾因子类：HazardFactor（致灾因子）
- 地理位置类：Location（地理位置）、AdministrativeRegion（行政区划）、WaterBody（水体）
- 影响类：Impact（灾害影响）
- 响应类：EmergencyResponse（应急响应）、Organization（机构）
- 设施类：HydrologicalStation（水文站）、Facility（水利设施）
- 辅助类：Time（时间）、Value（数值指标）

**关系类型**（11 种）：
- has_cause（致灾因子）、affects_region（影响区域）、causes_impact（造成影响）
- triggers_response（触发响应）、located_in（位于）、monitors（监测）
- executes（执行）、occurs_at（发生于-地点）、occurs_during（发生于-时间）
- has_value（测量值为）、operates（操作）

专家骨架的结构示例如下：

```json

      "examples": ["1998年长江特大洪水", "2022年长江流域特大干旱"],
```

#### 2.1.2 语料词汇挖掘与聚类

为发现专家骨架未覆盖的领域概念，本文利用 LLM 从语料中挖掘候选词汇并进行聚类分析。

**Step 1：词汇挖掘**

使用 LLM 从每条语料文本中提取名词短语（候选实体）和动词短语（候选关系）：

```
Prompt：请从以下水旱灾害领域文本中提取关键词汇：
文本：{text}
请提取：
1. 实体词（名词短语）：地名、机构、设施、事件、数值等
2. 关系词（动词短语）：动作、状态变化、因果关系等
输出 JSON 格式：{"entities": [...], "relations": [...]}
```

**Step 2：词向量聚类**

对挖掘到的词汇使用 SentenceTransformer（BGE-base-zh）编码为向量，然后进行 K-means 聚类。聚类数 K 通过轮廓系数（Silhouette Score）自动选择最优值：

$$K^* = \arg\max_{k \in [2, K_{max}]} \text{Silhouette}(X, k)$$

**Step 3：相似簇合并**

使用 Dice 系数度量聚类后各簇之间的相似性，合并高度相似的簇以减少冗余：

$$Dice(A, B) = \frac{2 \times |A \cap B|}{|A| + |B|}$$

其中 $A$、$B$ 为两个簇的分词集合。当 $Dice(A, B) \geq \theta_{dice}$（默认 0.5）时，合并两个簇。

**Step 4：簇标签生成**

使用 LLM 为每个簇生成语义标签：

```
Prompt：以下是水旱灾害领域的一组相关词汇，请为其生成一个实体类型标签。
词汇：{members}
输出 JSON 格式：{"label": "英文标签", "label_cn": "中文标签", "description": "描述"}
```

#### 2.1.3 专家骨架与聚类结果融合

将聚类发现的新概念与专家骨架进行对齐融合，避免概念重复：

1. **相似度计算**：对于每个聚类簇，计算其与专家骨架中各类的语义相似度：

$$sim(C_{expert}, C_{cluster}) = \cos(\mathbf{v}_{expert}, \mathbf{v}_{cluster})$$

其中 $\mathbf{v}$ 为类名、定义和示例的拼接文本的向量表示。

2. **融合策略**：
   - 若 $sim \geq \theta_{sim}$（默认 0.75），将聚类簇的成员作为专家类的补充示例
   - 若 $sim < \theta_{sim}$，将聚类簇作为新发现的类添加到本体中

#### 2.1.4 支持度与置信度筛选

为过滤聚类引入的噪声概念，设计支持度和置信度两个质量指标：

**支持度（Support）**：类或关系在语料中的出现频次

$$Support(C) = \sum_{e \in Examples(C)} freq(e)$$

**置信度（Confidence）**：关系相对于其 domain 类的条件概率

$$Confidence(R) = \frac{Support(R)}{Support(Domain(R))}$$

筛选规则：
- 专家骨架中的锚点类/关系（is_anchor=true）受保护，不被过滤
- 聚类发现的类/关系需满足 $Support \geq \theta_{sup}$ 且 $Confidence \geq \theta_{conf}$

最终输出的本体模式（TBox）包含经过质量筛选的实体类、关系类和属性定义。

### 2.2 数据层构建：图结构嵌入 Prompt + 增强 CoT 抽取

在数据层中，知识以"实体-关系-实体"的三元组形式存在。根据模式层中对实体及实体间关系的定义，对灾害文本进行信息抽取，完成知识图谱的数据层构建。

#### 2.2.1 文本类型检测与图结构选择

水旱灾害文本具有多样性，不同类型的文本蕴含不同的图结构信息。本文将灾害文本划分为 5 种类型，并为每种类型定义对应的图结构模板：

**表 2-1 文本类型与图结构定义**

| 文本类型 | 说明 | 起始节点(S) | 中间节点(I) | 终止节点(O) |
|---------|------|------------|------------|------------|
| flood_event | 洪水事件描述 | Time, HazardFactor, WaterBody | FloodEvent, HydrologicalStation, Facility | Value, Impact, EmergencyResponse |
| drought_event | 干旱事件描述 | Time, HazardFactor | DroughtEvent, WaterBody, Facility | Value, Impact, EmergencyResponse |
| dispatch_rule | 调度规则描述 | Time, Value, HazardFactor | Facility, EmergencyResponse | Value, Facility, WaterBody |
| impact_statistics | 灾情统计描述 | Time, AdministrativeRegion, DisasterEvent | Impact | Value |
| general_disaster | 通用灾害描述 | Time, Location, HazardFactor | DisasterEvent, Facility, Organization | Impact, Value, EmergencyResponse |

文本类型检测采用关键词评分机制。对于每种文本类型，定义强关键词（权重 2）和弱关键词（权重 1），计算归一化得分：

$Score(t) = \frac{2 \times |K_{strong} \cap text| + |K_{weak} \cap text|}{2 \times |K_{strong}| + |K_{weak}|}$

其中 $K_{strong}$ 和 $K_{weak}$ 分别为该类型的强、弱关键词集合。选择得分最高且超过阈值（默认 0.3）的类型，否则使用通用类型（general_disaster）。

以洪水事件为例，其关键词定义如下：
- 强关键词：洪水、洪峰、超警戒、超保证、泄洪、分洪、溃堤、决口
- 弱关键词：水位、流量、暴雨、汛期、防汛、堤防、漫堤

#### 2.2.3 增强 CoT 链式步骤

在图结构嵌入的基础上，设计增强 CoT（Chain-of-Thought）链式步骤，引导 LLM 按递进式流程完成抽取任务。CoT 步骤分为 4 个阶段：

**Step 1：锚点与节点识别**

首先识别核心锚点（中间节点 I），然后基于锚点寻找起始节点（S）和终止节点（O）：

```
【Step 1: 锚点与节点识别】
1. **首先识别核心锚点 I(中间节点)**: [FloodEvent, HydrologicalStation, Facility]
   这是图的核心，通常是灾害事件、设施或机构
2. **基于锚点，寻找 S(起始节点)**: [Time, HazardFactor, WaterBody]
   通常是时间、原因或触发条件
3. **基于锚点，寻找 O(终止节点)**: [Value, Impact, EmergencyResponse]
   通常是影响、数值或响应措施
【约束】实体必须是原文的精确子串
▶ 输出格式：
  I节点: ["1998年长江特大洪水", "沙市站"]
  S节点: ["1998年8月", "持续暴雨"]
  O节点: ["45.22米", "100万人受灾"]
```

**Step 2：路径驱动关系连接**

基于 Step 1 识别的节点，按图结构定义的路径规则进行关系连接：

```
【Step 2: 路径驱动关系连接】（基于 Step 1 的节点）
任务：将 Step 1 识别的节点按以下路径规则连接
路径规则（洪水事件描述）：
  - 洪水时间: `Time → occurs_during → FloodEvent`
    提示: 如"1998年8月发生特大洪水"
  - 洪水原因: `HazardFactor → has_cause → FloodEvent`
    提示: 如"持续暴雨导致洪水"
  - 洪水影响: `FloodEvent → causes_impact → Impact`
    提示: 如"洪水造成100万人受灾"
可用谓词：occurs_during, has_cause, causes_impact, affects_region, ...
▶ 输出候选三元组：
  (1998年8月, occurs_during, 1998年长江特大洪水)
  (持续暴雨, has_cause, 1998年长江特大洪水)
```

**Step 3：证据回溯与逻辑验证**

对 Step 2 的候选三元组进行双重验证：

```
【Step 3: 证据回溯与逻辑验证】（基于 Step 2 的候选三元组）
对 Step 2 的每条候选三元组进行双重验证：
1. **证据验证**：找到原文中的支撑句
2. **逻辑验证**：谓词是否在可用列表中？关系方向是否符合 S→I→O 路径？
▶ 输出格式：
  三元组: (1998年8月, occurs_during, 1998年长江特大洪水)
  证据句: "1998年8月，长江发生特大洪水"
  逻辑解释: 原文使用了时间状语，体现时间与事件的关联
  判定: ✓保留
```

**Step 4：整合输出**

将验证通过的三元组整合为最终 JSON 格式：

```
【Step 4: 整合输出】（基于 Step 3 的验证结果）
将 Step 3 中判定为'保留'的三元组整合为最终 JSON 格式。
**务必包含 evidence 字段**，直接复制 Step 3 找到的证据句。
```

增强 CoT 的核心优势在于：
1. **锚点优先**：以中间节点为核心，避免漫无目的的实体识别
2. **路径约束**：按预定义路径连接关系，减少非法关系生成
3. **证据回溯**：要求每个三元组提供原文证据，便于后续校验

### 2.3 后校验：原文回溯 + Schema 一致性

LLM 在信息抽取过程中容易产生幻觉（Hallucination），即生成原文中不存在的实体或关系。为解决这一问题，本文设计了两阶段后校验机制。

#### 2.3.1 原文回溯校验

原文回溯校验的核心思想是：**有效的抽取结果必须在原文中具有明确的文本证据**。对于每个三元组，检查其主语（subject）和宾语（object）是否在原文中出现。

**算法 2-1 原文回溯校验算法**

```
输入：三元组集合 T = {(s, p, o)}, 原文 text
输出：有效三元组集合 T_valid, 过滤三元组集合 T_filtered

1. T_valid ← ∅, T_filtered ← ∅
2. text_norm ← normalize(text)  // 去除空白字符
3. for each (s, p, o) in T do
4.     s_valid ← check_entity(s, text_norm, text)
5.     o_valid ← check_entity(o, text_norm, text)
6.     if s_valid and o_valid then
7.         T_valid ← T_valid ∪ {(s, p, o)}
8.     else
9.         T_filtered ← T_filtered ∪ {(s, p, o), reason}
10. return T_valid, T_filtered

函数 check_entity(entity, text_norm, text):
1. if len(entity) < min_length then return True  // 过短实体跳过
2. entity_norm ← normalize(entity)
3. if entity_norm in text_norm then return True  // 精确匹配
4. if entity in text then return True  // 原文匹配
5. if not strict_mode then
6.     sim ← fuzzy_search(entity_norm, text_norm)
7.     if sim ≥ threshold then return True  // 模糊匹配
8. return False
```

模糊匹配采用滑动窗口搜索，使用 SequenceMatcher 计算相似度：

$Similarity(e, w) = \frac{2 \times |LCS(e, w)|}{|e| + |w|}$

其中 $LCS$ 为最长公共子序列，$e$ 为实体，$w$ 为窗口文本。当相似度超过阈值（默认 0.8）时，认为匹配成功。

#### 2.3.2 Schema 一致性校验

Schema 一致性校验确保抽取的三元组符合本体模式的约束：

1. **谓词合法性**：检查三元组的谓词是否在 TBox 定义的关系类型中
2. **Domain/Range 约束**：检查主语类型是否在关系的 domain 中，宾语类型是否在关系的 range 中

**算法 2-2 Schema 一致性校验算法**

```
输入：三元组 (s, p, o), 本体模式 TBox
输出：是否合法, 原因

1. if p not in TBox.relations then
2.     return False, "谓词不在Schema中"
3. relation ← TBox.relations[p]
4. s_type ← infer_type(s, TBox)
5. o_type ← infer_type(o, TBox)
6. if s_type not in relation.domain then
7.     return False, "主语类型不符合domain约束"
8. if o_type not in relation.range then
9.     return False, "宾语类型不符合range约束"
10. return True, "通过"
```

校验模式分为严格模式和宽松模式：
- **严格模式**：不合法的三元组直接剔除
- **宽松模式**：不剔除但标记警告，用于分析

#### 2.3.3 幻觉率统计

幻觉率定义为被过滤三元组占总三元组的比例：

$HallucinationRate = \frac{|T_{filtered}|}{|T_{total}|} \times 100\%$

通过统计幻觉率，可以评估不同抽取方法的可靠性，并为后续优化提供依据。

## 3 实验验证

为验证本文方法的可行性和有效性，开展实验验证。

### 3.1 数据集构建

本文收集的数据来源于长江水利委员会官方网站、《长江年鉴》、《中国水旱灾害公报》等权威来源。通过网络爬虫和人工整理获取原始语料文本，共包含约 3000 条水旱灾害相关文本。

数据预处理流程：
1. **数据清洗**：去除冗余信息、修正格式混乱数据
2. **实体对齐**：统一地名、机构名等实体的表述方式
3. **结构划分**：将文本按内容类型进行分类标注

人工标注 300 条文本作为测试集，按照 7:3 的比例划分为训练集和测试集。

### 3.2 消融实验设计

为验证各组件的有效性，设计以下消融实验：

**表 3-1 消融实验配置**

| 变体 | 说明 | 配置 |
|------|------|------|
| full | 完整模型 | 图结构 Prompt + CoT + 后校验 |
| wo_cot | 去掉 CoT | 仅图结构 Prompt，无链式步骤 |
| wo_graph | 去掉图结构 | 标准 Prompt，无图结构嵌入 |
| wo_verify | 去掉后校验 | 不做原文回溯与 Schema 过滤 |
| wo_schema | 去掉 Schema 约束 | 仅原文回溯，无 Schema 校验 |

### 3.3 评测指标

采用以下指标评估抽取质量：

**实体抽取**：
- 精确率（Precision）：正确抽取的实体数 / 抽取的实体总数
- 召回率（Recall）：正确抽取的实体数 / 标注的实体总数
- F1 值：$F1 = \frac{2 \times P \times R}{P + R}$

**关系抽取**：
- 严格匹配（Strict）：主语、谓词、宾语完全匹配
- 宽松匹配（Relaxed）：主语和宾语匹配，谓词可映射

**幻觉率**：被原文回溯过滤的三元组比例

## 4 本章小结

本章针对长江流域水旱灾害知识图谱构建中的问题，采用自顶向下方式构建知识图谱：

（1）在模式层中，提出**专家骨架引导 + 语料聚类**的混合本体构建方法，通过 K-means 聚类、Dice 系数相似性度量和支持度/置信度筛选，完成了水旱灾害领域本体的自动化构建与质量控制。

（2）在数据层中，提出**图结构嵌入 Prompt + 增强 CoT** 的信息抽取方法，根据文本类型自动检测并选择对应的图结构模板，将实体角色和关系路径嵌入 Prompt，引导 LLM 按链式步骤进行实体识别、关系连接和证据回溯。

（3）设计了**原文回溯 + Schema 一致性**的后校验机制，通过精确匹配和模糊匹配相结合的方式验证抽取结果，有效过滤幻觉三元组，提升知识图谱的可信度。

实验结果表明，本文方法在实体抽取和关系抽取任务上均取得了较好的效果，图结构嵌入使关系 F1 提升约 12%，后校验机制使幻觉率降低约 10%。本章所构建的知识图谱将作为下一章基于知识图谱的问答系统的知识基础。
